ChatGPT GAS自動化、始め方の3手順

ChatGPTでGAS(Google Apps Script)の自動化を始めるやり方は、「①ChatGPTにコードを書いてもらう」「②権限の承認と社内ルールを確認する」「③小さく試して、動いたら定期実行にする」の3手順です。多くの解説は①で終わっています。ですが実際に詰まりやすいのは、②の承認画面や管理者の設定と、③の動作確認です。この記事では、Googleの公式ドキュメントとOpenAIの公式情報をもとに、社内で安全に動かすまでの流れをまとめます。

ChatGPTとGASで何が自動化できるのか

できるのは、Googleスプレッドシート・Gmail・Googleカレンダー・Googleドライブなどの決まった作業を、GASのプログラムでまとめて動かすことです。ChatGPTは、そのプログラムを考えて書く手伝いをします。

2つの使い方がある

ChatGPTとGASの組み合わせ方は、大きく2つあります。

  1. ChatGPTにGASのコードを書かせるだけ:できたコードをGASに貼りつけて動かします。動いているあいだ、AIは使いません
  2. GASからOpenAI APIを呼び出す:スプレッドシートの文章を要約・分類するなど、処理の途中でAIを使います
比べる点①コードを書かせるだけ②GASからAPIを呼ぶ
たとえばできること毎朝の集計、定型メールの下書き作成、フォーム回答の整理問い合わせ文の要約、アンケートの自由記述の分類
必要な契約ChatGPT(無料プランでも可)OpenAI APIの契約(ChatGPTとは別)
費用基本はGoogleアカウントの範囲内APIを使った量に応じて課金
気をつけることコードの中身の確認、権限の承認上の2つに加え、APIキーの管理と送るデータの扱い
向いている人まず定型作業を減らしたい人文章の判断が入る作業まで任せたい人

はじめての人は①から始めるのがおすすめです。外部にデータを送らず、費用もかからないので、社内の承認も通りやすくなります。

ChatGPTの有料プランとAPIは別の契約

ChatGPT Plusなどの有料プランに入っていても、APIを使う権利はついてきません。OpenAIのヘルプでは、ChatGPTのサブスクリプションとAPIの請求は別々に管理されると説明されています(OpenAI Help Center)。②の使い方をするなら、APIの管理画面で別に支払い方法を登録する必要があります。

始め方の3手順

3つの手順は、「頼み方を工夫してコードを書かせる」「権限を確かめて承認する」「小さなデータで試してから定期実行にする」です。順番に説明します。

手順1:ChatGPTにコードを書かせる(頼み方のコツ)

ChatGPTには、作業を細かく分けて伝えると、思いどおりのコードが返ってきやすくなります。たとえば次のように頼みます。

Google Apps Scriptのコードを書いてください。 ・対象:スプレッドシート「問い合わせ一覧」のシート「回答」 ・処理:C列が空の行だけ、B列の内容を読み、C列に「済」と書く ・条件:最初はログに出すだけで、シートには書き込まない「試しモード」をつける ・使うサービス:SpreadsheetAppだけ。メール送信はしない ・各行に日本語のコメントをつける

ポイントは3つです。

  • 「使うサービス」を決めておく:あとで説明する「権限の承認」の範囲が小さくなります
  • 「試しモード」をつけてもらう:いきなり本番のデータを書きかえる事故を防げます
  • コメントをつけてもらう:コードを読めない人でも、何をしているかを確かめやすくなります

ChatGPTが書いたコードは、そのままでは正しく動かないことがあります。古い書き方や、実在しない関数がまじることもあります。エラーが出たら、エラーの文をそのままChatGPTに貼って直してもらうのが近道です。

手順2:権限(スコープ)を確かめて承認する

GASを初めて動かすと、「このスクリプトがあなたのデータにアクセスする許可」を求める画面が出ます。Googleの公式ドキュメントでは、これを「認可スコープ」と呼んでいます。スクリプトに必要な権限(メールを読む、予定を作るなど)が、「Googleスプレッドシートの表示」のような、人が読める説明で表示されます(Google for Developers:Authorization scopes)。

承認する前に、次の点を確かめます。

  • 表示された権限が、やりたい作業に対して広すぎないか(たとえば集計だけなのに「Gmailの送信」が入っていないか)
  • 知らない外部サービスへの接続が入っていないか

使う権限は、設定ファイル「appsscript.json」の oauthScopes で自分で決めることもできます。公式ドキュメントは、公開するアプリでは「できるだけ狭いスコープを使う」よう求めています(Google for Developers:Authorization scopes)。また、ユーザーが権限を1つずつ選んで許可できる画面に対応するため、ScriptApp.requireScopes() などで承認の状態を確かめる方法も紹介されています(同上)。

手順3:小さく試してから定期実行にする

動作確認は「コピーしたデータ」→「試しモード」→「本番」の順で進めると安全です。

  1. 本番のスプレッドシートをコピーして、テスト用のファイルで動かす
  2. 試しモードで、ログに出た結果が想定どおりか確かめる
  3. 試しモードを外して、テスト用ファイルへ実際に書き込む
  4. 問題がなければ本番ファイルに切りかえる
  5. 最後に、トリガー(決まった時間に自動で動かす設定)を入れる

GASの「時間主導型トリガー」は、1分ごとから1か月ごとまでの間隔で、スクリプトを自動実行できます(Google for Developers:Installable triggers)。失敗したときはApps Scriptからメールで知らせが届きます(同上)。最初の数日は、このメールと実行ログを毎日見るようにすると安心です。

社内で動かす前に確認すること

会社のGoogleアカウント(Google Workspace)で動かすなら、まず管理者の設定と社内ルールを確認します。ここを飛ばすと、「承認画面で止まる」「あとで使用禁止になる」といったことが起こりやすくなります。

管理者の設定でGASが使えないことがある

Google Workspaceの管理者は、組織の人ごとにApps Scriptをオン・オフできます。初期設定はオンですが、オフにされると、スクリプトの作成・編集ができないだけではありません。トリガーやマクロなどの実行も止まります(Google Workspace管理者ヘルプ:Apps Scriptのオン/オフ)。部署(組織部門)やグループの単位で設定を分けることもできます(同上)。

さらに管理者は、アプリがGoogleのデータにアクセスする範囲を「信頼できる」「制限付き」「特定のGoogleデータ」「ブロック」から選べます。社内で作ったアプリを信頼する設定もあります(Google Workspace管理者ヘルプ:アプリのアクセス管理)。ブロックされたアプリについて、ユーザーが利用を申請し、管理者が承認する流れを作ることもできます(同上)。

「確認されていないアプリ」の警告について

承認の途中で「Googleはこのアプリを確認していません」という警告が出ることがあります。公式ドキュメントによると、スクリプトの所有者と利用者が同じGoogle Workspaceの組織にいる場合は、Googleの確認(審査)は不要です。一方で、組織の外の人が承認しようとすると警告が出ます(Google for Developers:Client verification)。確認を受けていないアプリは、承認できる外部ユーザーの数にも上限があります(同上)。

社外の人や取引先にも使ってもらう予定があるなら、早めに情報システム部門へ相談してください。

社内承認で伝えるとよい項目

承認を頼むときは、次の内容を1枚にまとめておくと話が早く進みます。

項目書く内容の例
目的たとえば「問い合わせ一覧の転記作業を減らす」
使うサービススプレッドシートのみ/Gmail送信あり、など
必要な権限承認画面に出た権限の一覧
外部への送信なし/OpenAI APIへ送る(送る項目も書く)
実行する人トリガーを設定する人のアカウント
止め方トリガーの削除方法と担当者

「実行する人」は特に大事です。トリガーは、だれが動かしたかに関係なく、トリガーを作った人のアカウントで動きます(Google for Developers:Installable triggers)。担当者が異動・退職したときの引きつぎ方も、あらかじめ決めておきましょう。

管理者向けには、組織内のApps Scriptの利用状況を見て管理する方法もまとめられています(Google for Developers:Monitor and control Apps Script use)。

GASからOpenAI APIを使うときの注意点

GASからOpenAI APIを呼ぶときに大事なのは、「APIキーをコードに直接書かない」「送るデータを決める」「使いすぎを防ぐ設定をする」の3つです。

APIキーはスクリプトプロパティに保存する

GASには、設定値を保存する「Properties Service」があります。全員で共有するスクリプトプロパティ、人ごとのユーザープロパティ、文書ごとのドキュメントプロパティの3種類です(Google for Developers:Properties Service)。APIキーをコードに直接書くと、コードを共有したときにキーも一緒に漏れてしまいます。キーはプロジェクトの設定画面からスクリプトプロパティに入れて、コードでは読み出すだけにします。

たとえば、次のような形です(モデル名は例です。使えるモデルは公式で確認してください)。

function askOpenAI(text) {
  // APIキーはコードに書かず、スクリプトプロパティから読む
  const apiKey = PropertiesService.getScriptProperties().getProperty('OPENAI_API_KEY');
  const res = UrlFetchApp.fetch('https://api.openai.com/v1/responses', {
    method: 'post',
    contentType: 'application/json',
    headers: { Authorization: 'Bearer ' + apiKey },
    payload: JSON.stringify({ model: 'gpt-5-mini', input: '次の文を1行で要約してください:' + text }),
    muteHttpExceptions: true // エラーでも止めずに中身を確認する
  });
  Logger.log(res.getResponseCode());
  return res.getContentText();
}

外部のAPIを呼ぶには UrlFetchApp を使います。muteHttpExceptions を指定すると、エラーが返ってきてもスクリプトが止まらず、自分でエラーを処理できます(Google for Developers:External APIs)。

OpenAIは、APIキーをメンバー同士で共有しないこと、有効期限を決めて定期的に入れかえることなどをすすめています(OpenAI Help Center:Best Practices for API Key Safety)。

送るデータと学習への利用

OpenAIの公式ドキュメントによると、APIに送ったデータは、自分から共有を選ばないかぎり、モデルの学習や改善には使われません。ただし、不正利用を監視するための記録は、法律で求められる場合を除き最大30日間保存されます(OpenAI:Data controls)。学習に使われないからといって、何を送ってもよいわけではありません。個人情報や取引先の情報を送ってよいかは、社内の規程で確認してください。

料金と使いすぎ対策

APIの料金は、モデルごとに100万トークンあたりの単価で決まっています。たとえば公式の料金ページでは、gpt-5-miniが入力0.25ドル・出力2.00ドル、gpt-5-nanoが入力0.05ドル・出力0.40ドルとなっています(2026年10月時点・最新は公式で確認)(OpenAI API Pricing)。

使いすぎを防ぐため、APIの管理画面では、一定の金額を超えたら知らせる「支出アラート」を設定できます。月ごとの上限に達したらAPIを止める「支出上限」もあります(OpenAI:Production best practices)。テスト用と本番用でプロジェクトを分けて、それぞれに上限を決めることもできます(同上)。GASのトリガーは自動で何度も動くので、上限は最初に設定しておきましょう。

動作確認で見落としやすいGASの制限

GASには1回の実行時間や1日の回数に上限があり、テストでは動いたのに本番で止まる原因になりがちです。主な上限は次のとおりです(Google for Developers:Quotas)。

項目個人のGoogleアカウントGoogle Workspace
1回の実行時間6分6分
外部への接続(URL Fetch)の回数1日2万回1日10万回
トリガーの合計実行時間1日90分1日6時間

(2026年10月時点・最新は公式で確認)

公式ドキュメントには、これらの上限は予告なく変わることがあると書かれています(同上)。動作確認では、次の点も見ておくと安心です。

  • データが増えたとき:テストで10行なら数秒でも、本番で数千行あると6分を超えることがあります。たとえば「1回に100行ずつ処理する」ように、ChatGPTへ直してもらう方法があります
  • 同じ行を2回処理しないか:「処理済み」の印をつける列を用意します
  • APIがエラーを返したとき:エラーの行を飛ばして記録する作りにしておくと、全体が止まりにくくなります
  • だれのアカウントで動くか:トリガーを作った人の権限で動くため、その人が見られないファイルは処理できません

ChatGPT×GAS自動化が向いている人・向いていない人

向いているのは「Googleのサービスで、毎回同じ手順をくり返している人」です。逆に、手順が毎回変わる作業や、社内でGoogle Workspaceを使っていない職場には向きません。

向いている人向いていない人
スプレッドシートやGmailで定型作業が多い会社員Microsoft 365が中心で、Googleのサービスをほとんど使わない職場
小さな仕組みを自分で直しながら育てたい人作ったあとの点検や修正をする人がいない職場
外注するほどではない作業を減らしたい個人事業主個人情報を多く扱い、社内規程で外部AIへの送信が禁止されている業務

デメリットと注意点

  • 保守する人が必要:ChatGPTが書いたコードでも、問題が起きたときに直すのは人です。仕様が変わったときに見直す担当者を決めておきましょう
  • 属人化しやすい:トリガーは作った人のアカウントで動くので、その人がいなくなると止まることがあります
  • 費用が見えにくい:APIを使う場合、トリガーの回数とデータの量で料金が変わります。支出上限は必ず設定しましょう
  • AIの出力は毎回同じとは限らない:要約や分類の結果は、ときどき人の目で確認する運用にしておくと安心です

よくある質問

プログラミングの知識がなくてもできますか?

簡単な自動化なら、ChatGPTにコードを書いてもらい、貼りつけて動かすところまではできます。ただ、エラーの直し方や、承認画面に出る権限の意味を理解する力は必要です。最初は、データを書きかえない「試しモード」つきのコードで練習するのがおすすめです。

ChatGPTの無料プランでもGAS自動化はできますか?

コードを書いてもらうだけなら、無料プランでもできます。ただし、GASの中からAIを呼び出す使い方は、ChatGPTとは別のOpenAI APIの契約と支払い設定が必要です。ChatGPTの有料プランにAPIの利用は含まれていません(OpenAI Help Center)。

「このアプリは確認されていません」と出たら危険ですか?

自分で作ったスクリプトや、同じ組織の人が作ったスクリプトでも、この警告が出ることがあります。所有者と利用者が同じGoogle Workspaceの組織なら、Googleの確認は不要とされています(Google for Developers)。だれが作ったか分からないスクリプトは、承認しないでください。

会社のアカウントでGASが動かないのはなぜですか?

管理者がApps Scriptをオフにしているか、アプリのアクセスを制限していることが考えられます(Google Workspace管理者ヘルプ)。自分で設定を変えることはできないので、情報システム部門に目的と必要な権限を伝えて相談しましょう。

自動実行が途中で止まるのはなぜですか?

よくある原因は、1回あたり6分の実行時間の上限を超えることです(Google for Developers:Quotas)。処理を小分けにする、処理済みの印をつけて続きから再開する、といった直し方があります。失敗の知らせのメールに原因が書かれているので、まずそこを確認しましょう。
